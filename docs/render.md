# 30ops render

`30ops render` 讀 [site.yaml](site-yaml.md)，產生收集端與節點的站點設定。先跑 validate，有錯就不產生任何檔案。

```sh
bin/30ops render --site site.yaml                       # 列出會產生的檔案、mode 與 owner
bin/30ops render --site site.yaml --out build           # 寫到 build/，路徑即安裝路徑
bin/30ops render --site site.yaml --diff                # 與 / 下已安裝的檔案比對，有差異回 1
bin/30ops render --site site.yaml --diff --root DIR     # 與 DIR 下的檔案比對
bin/30ops render --site site.yaml --compare-legacy DIR  # 與舊佈局的收集端語意比對，有差異回 1
```

產出寫到 `/` 之後，以 compose.env 啟動收集端：

```sh
docker compose --env-file /etc/30ops/compose.env -f /opt/30ops/collector/compose.yml up -d
```

## 原則

- **確定性：** 同一份 site.yaml 產生同樣的位元組，不含時間、主機名稱或亂數，主機依 site.yaml 的順序。CI 以 `tests/golden/render/sample-site/` 逐檔比對範例場域。
- **檔頭：** 文字檔第一行是 `# generated by 30ops X.Y.Z from site.yaml sha256:...; do not edit`。JSON 不能有註解，改由 `etc/30ops/manifest.json` 記錄每個檔案的路徑、mode、owner、sha256 與是否含秘密，v0.5 的 install 依它部署。
- **產品與場域分開：** 路由樹、抑制規則、scrape job、告警規則、儀表板與 compose 服務的定義在 repo（`collector/alertmanager/alertmanager.base.yml`、`collector/prometheus/prometheus.yml`、`collector/prometheus/rules/`、`collector/grafana/build-dashboard.py`、`collector/compose.yml`），render 只換掉場域相關的部分：目標、門檻、收件者、volume 名稱、保留期與時區。

## 秘密

render 不讀任何秘密檔。

- Alertmanager 用 `smtp_auth_password_file: /run/secrets/smtp`；compose 把 credentials 的檔案（compose.env 的 `OPS30_SMTP_PASSWORD_FILE`，沒有 SMTP 時是 `/dev/null`）掛成這個 secret。Grafana 的管理密碼同樣以 secret 掛入，檔案固定為 `/etc/30ops/secrets/grafana-admin.pass`。compose 的 secret 沿用主機上的擁有者與權限，所以這兩個檔案的擁有者要是容器執行的 uid（Alertmanager 65534、Grafana 472），權限 0400。
- eol-textfile 用 `--token-file`；pcap 拉取用 `SSH_KEY`。
- prometheus-pve-exporter 與 snmp_exporter 沒有讀檔的寫法：`pve.yml` 與 `snmp-auth.yml` 的秘密欄位輸出 `@secret:<credentials 名稱>`，manifest 標 `secret: true`，由 v0.5 install 代入並設 0640。
- `--diff` 比對這兩個檔案時不比秘密欄位，只說是否相同。

## 比對現行收集端

`--compare-legacy DIR` 的 DIR 是長得像舊收集端 `/` 的目錄：`scripts/fetch-legacy.sh` 的快照，或 CI 用的 `tests/fixtures/legacy-root/`（v0.3 時 repo 內手寫檔的副本，v0.4 起固定不變）。比對的是作用，不是位元組：

- 每個 job 的 targets 與 label 集合、scrape 設定、external labels。
- cron：每一行的排程、帳號、環境變數與指令。舊 clone 的路徑先換成 `collector.root` 與 `collector.log_dir`；檔案層級的 `AUDIT_QUIET_FROM`、`FW_EXPECT`、`AUP_EXPECT` 歸給讀它的那支腳本；`--token-file` 與 `--assets` 的路徑不比，assets 改比內容。
- allowlist 四個集合、service 的 EnvironmentFile 與 ExecStart、mount 的 What、Type、Options。
- Alertmanager 整份（秘密只比有沒有設）、Grafana datasources、gate 的 config.json 與 tools.json。
- pve.yml 與 snmp-auth.yml 的非秘密欄位。
- compose：兩個舊 compose 檔的服務集合、實際的 volume 名稱（舊專案名稱加 `_` 前綴）、Prometheus 與 VictoriaLogs 的保留期、syslog 時區與 Grafana 埠，對 compose.env。映像與掛載是產品，不比。

沒有差異時輸出為空、回 0。

### fetch-legacy.sh

```sh
scripts/fetch-legacy.sh USER@HOST OUTDIR
```

一個 ssh 連線，以 `sudo -n cat` 讀固定清單，不在主機上寫任何東西。秘密不離開主機：pve.yml 與 snmp-auth.yml 只留非秘密的鍵，其他檔案中名稱含 password、secret、token、api_key 的鍵值改為 `"MASKED"`；`grafana/admin_password`、token 檔與 SSH 金鑰不在清單內。快照的 `etc/timezone` 取 `/etc/localtime` 指向的時區（Ubuntu 用 timedatectl 改時區後，`/etc/timezone` 可能還是舊值）。提交到任何地方之前仍要自己看過一次。
